# Тестовая прошивка фейдера

`fader/fader.ino` — скетч для Arduino IDE. Читает потенциометр фейдера и шлёт MIDI на сервер, принимает с сервера положение и «двигает мотор» (пока — яркость светодиода).

## Какой режим выбрать

В начале скетча — `#define USB_MIDI`:

| плата                                  | `USB_MIDI` | что нужно                                           | группа в интерфейсе |
|----------------------------------------|-----------|-----------------------------------------------------|---------------------|
| Arduino Uno / Nano / Mega              | `0`       | ничего                                              | COM-порт            |
| ESP32 (WROOM, DevKit)                  | `0`       | ядро esp32 (Boards Manager → «esp32»)               | COM-порт            |
| Arduino Leonardo / Micro / Pro Micro   | `1`       | библиотека **MIDIUSB** (Library Manager)            | USB-MIDI            |
| ESP32-S2 / ESP32-S3                    | `1`       | ядро esp32 3.x, Tools → USB Mode → **USB-OTG (TinyUSB)** | USB-MIDI       |

Leonardo и S2/S3 можно прошить и с `USB_MIDI 0` — тогда они работают как COM-порт.
Если выбрать `USB_MIDI 1` для платы, которая так не умеет, компиляция остановится с понятной ошибкой.

## Подключение

```
потенциометр фейдера:  крайние выводы — GND и 5V (ESP32: 3.3V!), средний — A0
«мотор» (светодиод):   Uno/Nano/Leonardo — пин 9 через резистор 220 Ом; ESP32 — пин 2 (встроенный)
датчик касания:        кнопка между пином и GND, номер пина — в TOUCH_PIN (по умолчанию выключен: -1)
```

Пины, канал и номер фейдера — в блоке «Настройки» в начале скетча. `MIDI_CHANNEL` и `SERIAL_BAUD` должны совпадать с `MIDI_CHANNEL` и `HW_BAUD` сервера (по умолчанию 1 и 115200).

## Обмен с сервером

| что                    | MIDI                                  | направление      |
|------------------------|---------------------------------------|------------------|
| положение фейдера N    | Control Change, номер N, значение 0..127 | плата ↔ сервер |
| фейдер N взяли рукой   | Note On, нота N, velocity 127         | плата → сервер   |
| фейдер N отпустили     | Note Off, нота N                      | плата → сервер   |

В режиме COM-порта это те же 3 байта MIDI, просто через `Serial` на скорости 115200.

Пока мотор едет к присланному положению, прошивка свои значения не шлёт — иначе сервер принял бы движение мотора за руку и отобрал бы фейдер у интерфейса. Сервер дополнительно отбрасывает значения, совпадающие с только что отправленной целью (±2 в течение 300 мс).

Для настоящего мотора нужно дописать `motorDrive()` и `motorStop()` (драйвер, например TB6612 или L293D) — места помечены в скетче.

## Проверка на живой плате

1. Прошить скетч. **Закрыть монитор порта** в Arduino IDE — пока он открыт, сервер не сможет открыть COM-порт.
2. `npm run dev` в корне проекта, открыть http://localhost:5173, «Подключить».
3. В панели «Устройство» нажать «Обновить» — плата появится в своей группе. Выбрать её → «Подключить». Статус «Подключено».
4. Покрутить потенциометр — фейдер в интерфейсе едет следом, под ним «Последним двигал: физический фейдер».
5. Подвинуть фейдер в интерфейсе — меняется яркость светодиода.
6. Если подключён датчик касания: зажать кнопку — фейдер в интерфейсе блокируется («Сейчас управляет: физический фейдер»), отпустить — разблокируется.
7. Выдернуть USB — статус «Ждём устройство»; вставить обратно — через пару секунд снова «Подключено».

Что может пойти не так:

- **«COM3 занят другой программой»** — открыт монитор порта или другая программа держит порт.
- **USB-MIDI не открывается** — в Windows MIDI-устройство может держать только одна программа (закрыть DAW).
- **Значения в интерфейсе скачут** — шумит питание потенциометра; увеличить сглаживание (`0.2` → `0.1` в `loop()`).
- **Плата не появляется в USB-MIDI** — у ESP32-S2/S3 проверить USB Mode = USB-OTG (TinyUSB) и что кабель подключён к порту «USB», а не «UART».
