# fader-server — тестовый локальный сервер

Сервер-заглушка для проверки **Fader UI** без настоящего бэкенда.
Принимает значения фейдера по WebSocket, проверяет их, отвечает подтверждением и подробно логирует в консоль.

Стек: Node.js (>= 20) + TypeScript + Express + [`ws`](https://github.com/websockets/ws).
Express и WebSocket работают на **одном порту** — 8765, на который фронт стучится по умолчанию.

## Запуск

```bash
npm install
npm run dev        # с автоперезапуском при правке кода
```

Потом во фронте (`fader-ui`): `npm run dev` → открыть http://localhost:5173 → «Подключить».

В консоли сервера будет примерно так:

```
19:35:06.159 OK    client#1 подключился (127.0.0.1), всего клиентов: 1
19:35:06.166 RECV  client#1 fader#1 =  64 ████████████░░░░░░░░░░░░ seq=2 Δ=1мс
19:35:06.166 SENT  → client#1 {"type":"ack","id":1,"value":64,"seq":2,...}
19:35:06.167 WARN  client#1: пропуск seq 2 → 5 (потеряно 2)
19:35:06.167 ERROR client#1: неверное сообщение (не JSON): hello
```

Другие команды:

| команда              | что делает                          |
|----------------------|-------------------------------------|
| `npm start`          | запуск без автоперезапуска           |
| `npm run typecheck`  | проверка типов                      |
| `npm run build`      | сборка в `dist/`                    |
| `npm run start:prod` | запуск собранного `dist/index.js`   |

## Настройки (переменные окружения)

| переменная     | по умолчанию | что делает                                                     |
|----------------|--------------|----------------------------------------------------------------|
| `PORT`         | `8765`       | порт HTTP + WebSocket                                          |
| `HOST`         | `0.0.0.0`    | `0.0.0.0` — доступно из локальной сети, `127.0.0.1` — только с этой машины |
| `ACK`          | `1`          | `0` — не отвечать на сообщения                                 |
| `LATENCY_MS`   | `0`          | искусственная задержка ответа (проверить «медленный» сервер)  |
| `LOG_EACH`     | `1`          | `0` — вместо каждого сообщения печатать сводку раз в секунду   |
| `HISTORY_SIZE` | `500`        | сколько последних сообщений хранить для `/api/history`         |
| `SIM_HW_MS`    | `0`          | имитация физического фейдера: раз в столько мс он сам плавно едет в случайное положение. `0` — выключено |
| `SIM_HW_ID`    | `1`          | какой фейдер двигает имитация                                  |
| `LOCK_MS`      | `500`        | короткий захват: кнопки, клавиатура и железо занимают фейдер на столько мс после последнего изменения |
| `NO_COLOR`     | —            | `1` — без цветов в консоли                                     |

Пример (macOS/Linux): `LATENCY_MS=100 LOG_EACH=0 npm run dev`
Windows PowerShell: `$env:LATENCY_MS=100; npm run dev`
Проверить, что интерфейс двигается за «железом»: `$env:SIM_HW_MS=3000; npm run dev`

## Протокол WebSocket

**Клиент → сервер** (то, что шлёт фронт):

```jsonc
{ "type": "fader", "id": 1, "value": 64, "seq": 12, "ts": 1791634706755 }
// взял ручку / отпустил ручку
{ "type": "grab", "id": 1 }
{ "type": "release", "id": 1 }
```

Сервер проверяет: `type` — `"fader"`, `"grab"` или `"release"`, `id` и `seq` — целые числа >= 0, `value` — целое 0..127, `ts` — число.

**Сервер → клиент:**

```jsonc
// сразу после подключения
{ "type": "hello", "clientId": 1, "serverTs": 1791635706159, "message": "..." }
// на каждое корректное сообщение (если ACK=1)
{ "type": "ack", "id": 1, "value": 64, "seq": 12, "serverTs": 1791635706166, "deltaMs": 2 }
// захват изменился — всем; и новому клиенту сразу после hello. owner: номер клиента, "hw" или null (свободен)
{ "type": "lock", "id": 1, "owner": 2, "held": true }
// положение фейдера изменилось — всем клиентам, кроме автора; и новому клиенту сразу после hello
{ "type": "state", "id": 1, "value": 64, "source": "client", "by": 2, "serverTs": 1791635706166 }
{ "type": "state", "id": 1, "value": 30, "source": "hw", "serverTs": 1791635706200 }
// на некорректное сообщение
{ "type": "error", "reason": "value должен быть целым 0..127, пришло 300", "raw": "..." }
```

`source`: `"client"` — изменил один из интерфейсов (его номер в `by`), `"hw"` — физический фейдер (пока имитация или `POST /api/fader/:id`).

`deltaMs` = время сервера минус `ts` клиента. Это реальная задержка, только когда фронт и сервер запущены на одном компьютере, — иначе часы могут расходиться.

### Захват фейдера

Чтобы два интерфейса не тянули фейдер одновременно, им управляет только один — кто взял первым:

- `grab` занимает свободный фейдер до `release` (`held: true`). Если фейдер занят, клиенту приходит `lock` с текущим владельцем и `state` с текущим значением — его ручка возвращается на место.
- `fader` от того, кто фейдер не держит, тоже отклоняется (`lock` + `state`, без `ack`). Если фейдер свободен, `fader` занимает его коротко — на `LOCK_MS` (`held: false`): так кнопки и клавиатура не мешают друг другу.
- Физический фейдер главнее: его движение забирает захват у любого интерфейса (коротко, на `LOCK_MS`).
- Клиент отключился, не отпустив ручку, — захват снимается.

Ещё сервер следит за `seq` в рамках одного соединения и пишет предупреждение, если номер пропущен, повторился или пришёл не по порядку.

## HTTP

| метод и путь               | что возвращает                                              |
|----------------------------|-------------------------------------------------------------|
| `GET /`                    | страница статуса: текущее значение фейдера вживую + счётчики |
| `GET /health`              | `{ ok: true, uptimeSec }`                                   |
| `GET /api/state`           | значения фейдеров, подключённые клиенты, счётчики, настройки |
| `GET /api/history?limit=50`| последние принятые сообщения                                |
| `POST /api/reset`          | сбросить значения, историю и счётчики                       |
| `POST /api/fader/:id`      | как будто физический фейдер подвинули: тело `{ "value": 0..127 }`, уходит всем как `state` с `source: "hw"` |

CORS открыт для всех, поэтому ручки можно вызывать и с фронта.

## С телефона / другого компьютера

При старте сервер печатает адрес в локальной сети, например `ws://192.168.1.42:8765`. Его нужно вставить в поле адреса во фронте.
Если не подключается — проверьте, что устройства в одной сети и что файрвол пропускает порт 8765.

## Структура

```
src/
  index.ts     запуск: HTTP-сервер, Express + WebSocket на одном порту, остановка по Ctrl+C
  http.ts      Express: страница статуса и /api/*
  ws.ts        WebSocket: приём, проверка, ack, контроль seq, рассылка state
  sim.ts       имитация физического фейдера (SIM_HW_MS)
  protocol.ts  типы сообщений и валидация (зеркало фронтового protocol.ts)
  state.ts     состояние в памяти
  config.ts    переменные окружения
  logger.ts    цветной лог в консоль
```
