# Fader UI — прототип

Веб-интерфейс с одним фейдером для MIDI-контроллера с моторизированными фейдерами.
Отправляет положение фейдера на сервер по WebSocket и сам двигается, когда фейдер меняют с другого интерфейса или физически.

Стек: TypeScript + React + Vite.

## Запуск

```bash
npm install
npm run dev
```

Открыть http://localhost:5173. Благодаря `host: true` в `vite.config.ts` интерфейс открывается и с телефона в той же сети (по IP компьютера).

Адрес сервера по умолчанию — тот же компьютер, что отдал страницу, порт 8765: открыли `http://192.168.1.42:5173` на телефоне — подключится к `ws://192.168.1.42:8765`. Его можно поменять в поле вверху страницы (запоминается в браузере) или через `.env`:

```bash
cp .env.example .env   # и поправить VITE_WS_URL
```

## Что отправляется

Каждое изменение фейдера уходит одним JSON-сообщением:

```json
{ "type": "fader", "id": 1, "value": 64, "seq": 12, "ts": 1791634706755 }
```

| поле    | что это                                                   |
|---------|-----------------------------------------------------------|
| `type`  | всегда `"fader"`                                          |
| `id`    | номер фейдера (настраивается в интерфейсе)                |
| `value` | положение 0..127 — как у MIDI Control Change              |
| `seq`   | порядковый номер, помогает заметить потерянные сообщения  |
| `ts`    | время отправки на клиенте, мс                             |

> Формат — предложение фронта, **нужно согласовать с backend**. Всё про формат лежит в `src/lib/protocol.ts`.

Когда пользователь берёт ручку, уходит `{ "type": "grab", "id": 1 }`, когда отпускает — `{ "type": "release", "id": 1 }` (после последнего значения).

Частота ограничена: не чаще одного сообщения в 20 мс (настраивается, 0 — без ограничения). Последнее значение при остановке фейдера уходит всегда. Одинаковые значения подряд не дублируются.

## Что принимается

Все входящие сообщения пишутся в лог (`← RECV`). На четыре из них интерфейс реагирует:

- `hello` — запоминается свой номер клиента;
- `state` — фейдер встаёт в присланное положение (если `id` совпадает с «ID фейдера»). Пока пользователь держит ручку, `state` игнорируются, чтобы она не прыгала под пальцем. Под фейдером видно, кто двигал последним: вы, другой интерфейс или физический фейдер.
- `hw-status` — список устройств и что подключено, для панели «Устройство».
- `lock` — кто сейчас управляет фейдером. Если другой интерфейс или железо, ручка и тестовые кнопки блокируются и видно, кто занял. Если фейдер забрали прямо во время движения (кто-то взял раньше или двинули железо), ручка бросается и встаёт в значение с сервера.

`ack` и `error` пока только в логе.

## Что есть в интерфейсе

- **Фейдер** — мышь, палец, клавиатура (↑/↓ ±1, PgUp/PgDn ±10, Home/End — 0/127).
- **Статус соединения** — подключено / подключение / переподключение / отключено / ошибка, время с момента подключения.
- **Открыть на телефоне** — на ПК (страница открыта как `localhost`) показывается QR-код с адресом интерфейса в локальной сети: навёл камеру телефона — открылось, IP вводить не нужно. Если сетей несколько (Wi-Fi, хот-спот, VPN), можно выбрать нужную; настоящие сети идут первыми, VPN и виртуальные — в конце. Адреса отдаёт сам Vite (`/__fader/lan`, плагин в `vite.config.ts`), поэтому работает при `npm run dev` и `npm run preview`.
- **Автопереподключение** — если связь пропала не по кнопке «Отключить» (упал сервер, моргнул Wi-Fi), интерфейс сам пробует снова через 1, 2, 5, затем каждые 10 с. Видно номер попытки и обратный отсчёт, кнопка «Сейчас» — попробовать без ожидания. На телефоне повтор сразу, когда вернулась сеть или снова открыли вкладку. «Отключить» останавливает попытки. После переподключения фейдер встаёт в положение с сервера: то, что двигали без связи, не отправляется.
- **Счётчики** — отправлено, получено, «не ушло» (двигали фейдер без соединения), сообщений в секунду, последнее отправленное значение, `seq`, байт.
- **Устройство** — выбор платы с фейдером на сервере: COM-порты (Uno, Nano, ESP32), USB-MIDI (Leonardo, Pro Micro, ESP32-S2/S3) или имитация; «Обновить», «Подключить» / «Отключить», статус и ошибка (например, порт занят). Выбор общий для всех интерфейсов.
- **Тестовые действия** — отправить 0 / 64 / 127 / любое значение, повторить текущее.
- **Логи** — время с миллисекундами, фильтры по типу (отправлено, получено, инфо, предупреждения, ошибки), автопрокрутка, выгрузка в `.txt`. Расшифровываются коды закрытия соединения (например, 1006 — сервер не запущен). Всё дублируется в консоль браузера с префиксом `[fader-ui]`.

## Структура

```
src/
  lib/protocol.ts          формат сообщений, диапазон 0..127
  hooks/useWebSocket.ts    подключение, отправка, счётчики
  hooks/useLogger.ts       журнал событий
  components/Fader.tsx     вертикальный фейдер
  components/StatusPanel.tsx
  components/DevicePanel.tsx  выбор физического устройства
  components/LogPanel.tsx
  App.tsx                  сборка экрана, ограничение частоты, настройки
```
